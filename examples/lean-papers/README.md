# Checking two more papers with Lean and Trackio

The same method as [`../lean-claims`](../lean-claims) (Attention Is All You Need), applied to:

| Folder | Paper | What is checked |
|---|---|---|
| [`memorization/`](memorization) | Morris et al., *How much do language models memorize?* (arXiv:2505.24832) | The paper's tables and formulas against each other (`Paper.lean`); the capacity experiment of Section 3, rerun on Hugging Face Jobs (`Claims.lean`) |
| [`adam/`](adam) | Kingma & Ba, *Adam: A Method for Stochastic Optimization* (arXiv:1412.6980) | The algorithm and its stated bounds (`Spec.lean`); that the code we ran implements Algorithm 1 (`Conformance.lean`); the experiments of Section 6, rerun on Hugging Face Jobs (`Claims.lean`) |

Each folder is a Lake project that needs only Lean's core library (no Mathlib):

```bash
cd adam && lake build
cd memorization && lake build
```

Each `*Runs.lean` is generated by `trackio export --format lean` from the Trackio project the
training script logged. The scripts ran on Hugging Face Jobs, launched with
[`run_on_hf_jobs.py`](run_on_hf_jobs.py), which installs a Trackio wheel so every run
records the SHA-256 of the script it ran and the job's ID. `trackio verify` checks both
against the script in this folder and against the copy the job executed.

## Results at a glance

**Memorization.** Most of the paper's numbers fail to agree with each other: the "3.5–3.6
bits per parameter" headline holds for 3 of Table 1's 16 rows, Figure 6's α is outside its
own error bar, Tables 3 and 4 use α = 3.54 rather than the stated 3.642 and give two results
for one configuration, and the membership-inference law as printed predicts Table 2 in
reverse order. The rerun supports the qualitative claims (small datasets are memorized
completely, memorization plateaus, capacity scales with parameters) but at 3% of the
paper's training steps reaches only 69–81% of Table 1's capacities.

**Adam.** The code that ran implements Algorithm 1 exactly. The step-size bound, the AdaMax
bound and Theorem 4.1 are false as stated. Of Section 6's seven empirical sentences, two hold
in our rerun, two are ties the paper reads as wins, and three are contradicted, including
the claim that `v̂` is dominated by ε (it exceeds ε by four orders of magnitude).

Details are in each folder's README.

## Three kinds of checks

1. **The paper against itself.** Numbers transcribed from the paper (tables, formulas, the
   text) are checked for consistency with exact rational arithmetic. Real functions
   (√, exp, the sigmoid) are enclosed in intervals with rational endpoints, so a theorem
   about them is still a proof, not a floating-point estimate.
2. **The paper's math.** A bound or theorem is checked on a concrete instance: if Lean
   computes a case that violates it, the statement is false as written.
3. **The paper's experiments.** Each empirical sentence becomes a decidable predicate on the
   logged metrics, and the theorem states whether the rerun supports it or contradicts it.
   Preconditions that make the comparison meaningful (learning rates chosen from the
   interior of their grid, every result averaged over three seeds, the code that ran is the
   code that was specified) are theorems too.
